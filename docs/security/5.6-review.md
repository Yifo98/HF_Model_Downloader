- `npm audit --json` 当前为 0 个已知漏洞。

本复核参考 [Electron 官方安全清单](https://www.electronjs.org/docs/latest/tutorial/security) 与 [Hugging Face 文件下载元数据说明](https://huggingface.co/docs/huggingface_hub/main/package_reference/file_download)。

## 威胁模型

重点防护以下输入和边界：

- 被篡改的 renderer、iframe 或不可信页面调用特权 IPC
- 恶意 Endpoint、SSRF、私网/保留地址与危险重定向
- Token 被持久化、进入日志或发送给镜像/自定义源
- 任意路径读写、目录穿越、符号链接逃逸与 Windows 特殊文件名
- 同名仓库、可变 revision、错误分片续传和同大小不同内容
- 超大清单、超大 API 响应、磁盘写满与并发实例竞争
- 恶意或被替换的 GitHub Release 资产、平台错配与缺失校验文件
- 删除历史时越界删除、符号链接逃逸或误删其他记录仍引用的文件
- 打包时误带旧截图、用户数据、历史或秘密

## 已落地控制

### Electron 与 IPC

- `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、`webSecurity: true`
- 默认拒绝权限、webview、新窗口和非可信导航
- 正式包 CSP 禁止任意网络连接，开发 CSP 仅允许本机 HMR
- 所有 IPC 校验主窗口、主 frame 与可信 renderer URL
- 外链固定为 Hugging Face Models 官方页
- 应用级单实例锁避免两个进程同时写历史、分片和目标文件
- 历史同步、删除、受控目录打开与更新检查各自使用窄化 IPC，不暴露任意路径或任意 URL

### Token 与网络

- Token 不进入 Preferences、History、DownloadUpdate 或日志
- Token 只允许发送到 `https://huggingface.co`
- 远端 Endpoint 必须使用 HTTPS
- 正式打包版只允许官方源和内置 HF Mirror，自定义远端仅供开发模式调试
- DNS 解析拒绝 loopback、私网、链路本地、多播和保留地址
- 兼容 Clash 等代理的 RFC 2544 synthetic DNS；直接访问该保留网段仍被拒绝
- 每次重定向重新校验目标；跨源跳转删除 Authorization
- API 响应上限为 8 MiB，请求、响应头和流读取均有超时

### 文件系统与下载

- 下载、打开目录和定位文件只允许用户批准根目录
- realpath/lstat 阻断符号链接、重解析点和目录逃逸
- 拒绝路径穿越、控制字符、Windows ADS、设备保留名、尾点/尾空格与大小写冲突
- 清单固定到 commit revision；输出目录使用 `owner/repo`
- 分片身份绑定 Endpoint、仓库、revision 与文件路径，续传要求强 ETag
- 续传同时校验 Content-Range 起止、总量、Content-Length 与固定清单大小
- LFS 校验 SHA-256，普通 Git 文件校验 blob OID
- 既有文件只有可信哈希通过时才会跳过
- 下载前重新读取清单，并检查已知总量、10% 与 512 MiB 固定安全余量
- JSON 状态文件限制 8 MiB，采用 `0600` 权限与原子替换
- 历史刷新只核对记录绑定的受控下载根；不会借刷新动作扫描其他本地目录
- 本地文件删除需要用户显式选择“记录与文件一起删除”，并重新执行 realpath、根目录和共享引用检查
- 只删除记录时不会触碰本地文件；删除文件后不自动清理父目录，避免移除用户自己创建的空目录结构

### 便携更新

- Release 来源固定为 `Yifo98/HF_Model_Downloader`，只允许 `api.github.com`、`github.com`、`objects.githubusercontent.com` 与 `release-assets.githubusercontent.com` 的必要 HTTPS 请求
- 资产必须匹配当前 platform / arch 的 `portable.zip` 命名，不接受 renderer 提供的任意下载 URL
- 更新 ZIP 与 `SHA256SUMS.txt` 必须来自同一 Release，文件名经过白名单解析并要求 SHA-256 完全一致
- 校验失败、校验文件缺失、平台资产缺失或下载不完整时停止更新准备
- 未签名版本只下载、校验并揭示便携包；不会静默替换正在运行的应用，也不会伪称“安装完成”

### Windows 目录式便携边界

- 发布构建使用 electron-builder `--win dir --x64`，把完整 `win-unpacked` 运行目录放入 ZIP；不再生成 NSIS portable wrapper，也不在 Release 顶层发布 EXE
- ZIP 根启动器会先验证便携标记与内部 EXE，创建项目内数据目录，并在 Electron 启动前把 `APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP`、Chromium userData 和磁盘缓存指向项目内；它不安装服务、不修改注册表、不写系统配置
- 主进程只接受绝对、已存在、自身非符号链接、含便携标记且包含当前 EXE 的便携根；非法环境值会被忽略并退回经过同样目录校验的本地运行目录
- 每个受管运行目录创建后还会执行 lstat/realpath 包含性检查；更新目录也经过同一检查，拒绝通过数据子目录符号链接或 junction 逃出便携根
- Windows 目录式便携版不自动读取或重写用户配置盘上的旧 Electron 数据，避免迁移逻辑再次触碰 C 盘
- ZIP 内的便携标记允许直接双击内部 EXE 时恢复解压根；标记缺失时数据仍只落到 EXE 所在目录
- Windows 的 appData、默认下载、缓存、userData、session、日志、crashDumps 和 temp 均指向项目根内 `HF_Model_Downloader_Data/`
- 发布校验要求内部 EXE、`resources/app.asar`、locale、PAK、V8 snapshot 和图形 DLL 存在，同时拒绝历史、Token、会话、缓存、日志与下载内容进入 ZIP
- 当前自动化只验证目录结构、路径策略和交叉构建结果；Windows junction/reparse point 与 SmartScreen 行为仍需要 Windows x64 真机复核

## 剩余风险与正式发布门槛

### 仍需完成

1. macOS 完成 Developer ID 签名、公证和 Gatekeeper 真机验证。
2. Windows 完成 Authenticode、目录式 portable 数据落点与 reparse point 真机验证。
3. 分别在 Apple Silicon、Intel Mac 与 Windows x64 真机复核图标、首次启动、目录落点和更新替换流程。
4. 配置 Electron fuses 与 ASAR integrity，再做正式包回归。
5. 增加本地 HTTP 集成测试，覆盖重定向、Range、取消、超时和并发 worker。

### 已知残余风险

- DNS 校验与实际连接之间仍存在理论上的 rebinding TOCTOU 时间窗。
- 文件系统检查与最终写入之间仍存在同机恶意进程竞争窗口。
- 内置镜像如不提供可信 commit 或内容哈希，5.6 会选择拒绝不安全流程，而不是降级到可变 `main`。
- 源 Logo 为用户选定的 1254×1254 RGB、无 Alpha 位图；ICNS/ICO 保持同一视觉内容，但不同系统蒙版下的边角呈现仍需真机确认。
- GitHub Release 与 `SHA256SUMS.txt` 同站托管时，若账号或 Release 同时失陷，攻击者可能一并替换资产和校验值；代码签名仍是正式发布必须补齐的身份链。
- 安装链仍包含少量上游已弃用的传递依赖提示；当前 `npm audit` 为 0，但正式发行仍应持续跟踪 Electron 与打包器更新。
